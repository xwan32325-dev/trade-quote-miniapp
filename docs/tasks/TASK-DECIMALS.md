# 本次任务：单价小数位自适应，消除「凑整导致的金额偏差」

## 问题

上一版为了满足「单价 × 数量 = 金额」，把行单价一律取 2 位小数，结果**大批量 + 低单价**的行会明显少算：

```
实测：EVA 收纳袋 2000 件，真实分摊金额 $946.89
      单价取 2 位 → 0.47 × 2000 = $940.00        ← 少算 $6.89
      同理 100,000 件的便宜货，误差可达数百美元
```

外贸实务中，低价大批量的单价本来就常写 4 位小数（如 USD 0.4734）。所以：**单价位数按需自适应**。

## 一、新规则（严格照抄）

```
分摊额_i = 整单总价 × (行货值_i ÷ 整单货值)          // 整单货值为 0 → 占比 0
选位数 d_i：从 2 开始递增到 6，取第一个满足下面条件的 d：
            | round(分摊额_i ÷ 数量_i, d) × 数量_i − 分摊额_i | ≤ 0.01
            若 2~6 位都不满足，则取 6
行单价_i = round(分摊额_i ÷ 数量_i, d_i)
行金额_i = round(行单价_i × 数量_i, 2)
```

**收尾（保证合计严格等于整单总价）**：
```
差额 = round(整单总价 − Σ 行金额, 2)
若 |差额| > 0.001：
    把差额加到【最后一行】金额上（金额 = 原金额 + 差额）
    最后一行单价 = 该行新金额 ÷ 数量（保留到 6 位内能凑准的位数；数量为 0 则单价为 0）
整单总价 = Σ 行金额          // 展示用，必须严格等于各行金额之和
```

- 数量为 0 / 货值为 0：行单价、行金额、占比一律为 0，不得 NaN
- 预期效果：每一行的金额与该行真实分摊额误差 ≤ 1 分，且 `单价 × 数量 = 金额`、`Σ 行金额 = 整单总价` 同时成立

## 二、展示

- 结果区明细表、导出单据、保存记录、复制文本**统一用同一组数**
- 单价按 `d_i` 显示（2 位就显示 2 位，需要 4 位就显示 4 位），不要把 4 位小数截成 2 位
- 导出 payload：`items[]` 每行 `{ productName, qty, unitPrice, totalPrice }`，`totalPrice = round(unitPrice × qty, 2)`

## 三、断言（更新 `scripts/verify-incoterms.mjs` / `verify-manualprice.mjs`）

1. 每行 `round(unitPrice × qty, 2) === totalPrice`
2. `Σ totalPrice === 整单总价`（严格，容差 0.001）
3. **每行 `|totalPrice − 该行真实分摊额| ≤ 0.01`**（这是本次的核心断言）
4. 低单价大批量用例：单价 0.4734、数量 200000 → 误差 ≤ 0.01（上一版会差几十美元）
5. 手动定价：`Σ 行金额 === 手填总价`（严格）
6. 数量 0 / 货值 0 无 NaN
7. 单行情形：`unitPrice × qty === totalPrice`，且单价位数选得最小（能 2 位就别用 4 位）
